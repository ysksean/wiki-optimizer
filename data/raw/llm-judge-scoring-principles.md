# LLM judge 채점 원칙 실전 교훈

RM 채점 judge(41항목 근거 기반 채점)를 두 달간 QA 루프 돌리며 확정된 원칙들.
각각 실제 품질 사고에서 나왔다.

## 1. 결정론이 이미 정한 것을 LLM이 재판정하게 하지 마라

근거 문서의 사업 귀속은 업로드 시점 `opportunity_id`가 이미 결정론으로 정한다.
그런데 judge에 "이 근거가 이 사업 것인지" 유관성 기각 규칙을 줬더니 — 마스터의 사업명이
코드성 값이고 문서에는 실제 명칭이 적힌 케이스에서 **완전히 정당한 근거를 전량 기각**,
8항목 중 3항목이 통째로 Unknown이 됐다.
표기 차이(약칭·영문/한글·법인 형태·구 명칭)는 상시 발생하므로 오탐도 상시화된다.
→ judge의 2차 기각을 폐지하고 수용 방향을 명시("표기가 달라 보여도 버리지 않는다").
단, 항목 유관성(이 행이 이 기준에 답하는가)은 여전히 judge 몫 — 축을 구분해서 풀었다.

**일반화**: 시스템이 결정론으로 보장하는 속성에 LLM의 확률적 재검증을 겹치면
안전장치가 아니라 오탐 발생기가 된다.

## 2. LLM은 오늘 날짜를 모른다 — 매 호출 주입

"최근 3년 이내 수행경험" 같은 기간 조건을 근거 속 날짜와 비교하려면 오늘 날짜가 필요한데
LLM은 모른다 (구축년도 2022년을 "3년 이내"로 판정한 사고).
수리 디테일 3가지가 전부 함정 회피:
- `__init__`/`lru_cache`에 박지 않고 **매 호출 `date.today()`** — 장수 프로세스 날짜 고착 방지.
- 합성 위치를 `__call__`에 — 레인별로 system_prompt를 대체하는 경로에서도 날짜 규칙이 안 빠지게.
- 역방향 명시: "오래됐다는 이유만으로 근거를 버리지 않는다" — 기간 규칙이 문서 기각으로 오독되는 것 방지.

## 3. 침묵 ≠ 부정 (silence is not evidence)

복수 조건 채점 구간에서 '확인 불가'(근거의 침묵)를 '불가'로 읽고 하향하는 판정 오류.
→ 원칙 블록에 일반 규칙: "복수 조건 구간은 **확인된 조건**으로 고르고, 침묵을 이유로
하위 조건으로 하향하지 않는다." 환각 방지 원칙과 쌍: "침묵 = 판단 불가 사유이지 부정 단정의 근거가 아니다."

## 4. 레인별 프롬프트 손복사본은 규칙 유실의 온상

영업/입찰/계약 레인이 판정 원칙 블록을 각자 들고 있으면, 원칙을 고칠 때 한 레인이 빠진다
(실제로 계약 레인이 입찰 프롬프트로 실행되는 이관 누락 사고 선행).
→ 원칙 수정 시 전 레인 동시 수정 + **프롬프트 배타성/포함 회귀 테스트**로 고정.
프롬프트도 코드다 — 중복 블록에는 중복 코드와 같은 drift가 생긴다.

## 5. Structured output 견고성 — coerce의 구멍은 테스트 입력이 가린다

LLM이 배열 필드를 JSON 문자열로 감싸 반환하는 케이스는 BeforeValidator
(`coerce_json_encoded_list`)로 흡수하고 있었는데, 간헐 502가 계속 남았다.
원인: `json.loads`의 기본 `strict=True`는 **문자열 값 안의 날 제어문자(줄바꿈·탭)를 거부**한다.
한국어 다줄 서술에서 LLM이 `\n` 이스케이프 없이 실제 줄바꿈을 넣으면 파싱 실패 →
원값(str)이 검증에 도달 → ValidationError → 5xx.
`strict=False`로 흡수하되, JSON 배열로 파싱되는 문자열만 흡수하고 그 외는 원값 유지(계약 불변).

**메타 교훈**: 기존 테스트는 `json.dumps`로 입력을 만들어 항상 이스케이프된 상태였다 —
**LLM 출력의 실패 모드를 재현하려면 테스트 입력도 LLM처럼 더럽게 만들어야 한다.**

**진단 팁**: LLM run이 시작돼 trace에 토큰이 찍혀 있으면 인증·권한 계열은 무죄
(그 전에 죽었을 것). 에러 스택의 pydantic 필드 경로가 1차 단서.
