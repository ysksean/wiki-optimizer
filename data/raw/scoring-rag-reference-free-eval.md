# 채점 RAG 전환과 reference-free 평가 파이프라인

## A. 문서 근거를 전체 투입 → 항목별 hybrid top-k로

평가 항목별 LLM judge에 문서 **청크 전체**를 통째로 넣던 구조(항목 수 × 문서 크기만큼
토큰, 대형 문서면 컨텍스트 초과 + needle-in-haystack)를 항목별 검색 top-k로 전환.

설계 판단들:

- **Phase 0 = 측정 먼저.** 실물 문서 1~2건에 항목↔정답청크 라벨을 만들어 recall@k·NDCG
  벤치 하네스부터. **mock 라벨로 튜닝 금지** — 이전에 mock 데이터로 유사도 튜닝했다가
  실데이터에서 무효가 된 선행 교훈이 있었다.
- **recall 중심 튜닝.** 근거 누락 = 억울한 N/A(사람 헷징 부담 증가)이고, 무관 청크는
  judge가 걸러준다. precision은 judge에게 위임하고 retrieval은 회수에 집중 —
  "판정자가 뒤에 있는 RAG"의 튜닝 축은 일반 RAG와 다르다.
- **싼 레버부터**: 항목별 검색 쿼리 사전 정의(평가 기준 원문은 추상적이라 도메인 키워드 병기),
  멀티 쿼리 합집합(사전 생성이라 런타임 비용 0), 검색 0건 시 전체 투입 폴백(소형 문서 한정).
  rerank·convex 결합은 벤치가 병목을 증명한 뒤(Phase 2).
- **인덱스 헬스가 침묵 장애 지점**: 인제스트 임베딩 호출이 죽으면(예: 토큰 만료)
  embedding NULL → 벡터 레인이 조용히 죽고 키워드 검색만 남는다. 하이브리드 검색은
  degrade가 티가 안 나므로 임베딩 성공률 지표 + NULL 백필 경로가 필요.
- 검색 스택은 기존 검증된 것 재사용 (pgvector 코사인 + 형태소 풀텍스트 + RRF) —
  채팅 레인에서 검증된 스택을 채점 레인에 이식.

## B. Reference-free LLM 평가 — "자기 프롬프트의 규칙을 뒤집어 지표화"

폐쇄망 제약으로 관리형 evaluator를 못 붙임 → Langfuse "External Evaluation Pipelines"
패턴으로 trace를 읽어 내부 LLM으로 품질을 판정하고 Score로 되쓴다.

핵심 아이디어: **정답 셋 불요(reference-free)** — 각 생성 Task가 자기 프롬프트에서
스스로에게 건 규칙(출처 표기·수준 정의·정본 준수)을 뒤집어 평가 지표로 만든다.
"프롬프트가 약속한 것을 산출물이 지켰는가"는 golden set 없이도 판정 가능하다.

운영 디테일:
- 지표 rubric은 코드로 정본화 (`rubrics.py` — LLM 지표 + 결정론 지표 혼합).
- 척도 변경(0~1 → 1~5) 시 구 지표 purge 경로를 같이 만든다 — 척도 혼재가 대시보드를 오염.
- 평가 단위를 명확히: 중간 판단은 제외하고 최종 산출물 단위로 고정 (감사 대상의 경계 정의).
- 멱등 재실행 + `--dry-run` + `--max-items`로 LLM 콜 수 통제 — 배치 평가도 비용 있는 job이다.
- 본격 확대 전 `--dry-run --limit 3 --report`로 Task별 점수·사유 캘리브레이션.

## C. HITL 프런트 — interrupt에 묶인 transient UI는 자동 발화와 레이스한다

에이전트 채팅에서 ask_user 카드(interrupt 상태에 묶인 UI)가 떠 있는데 배경 작업 완료
요약이 자동 발화되면, 새 run의 상태 이벤트가 interrupt를 클리어해 **카드가 사라지고
답변 기회가 영구 유실**된다. run이 멈추면 `isRunning=false`가 되므로 "실행 중 아님"
가드만으로는 못 막는다.
→ interrupt 대기 상태를 게이트로 제공하고, 자동 발화는 해제까지 유예(큐 유지, 유실 없음).
**사용자 직접 행동은 게이트 밖** — 사용자가 새 입력을 보내는 건 본인의 선택이므로 차단하지 않는다.
일반화: interrupt/HITL 기반 UI에서는 "시스템이 시작하는 발화"와 "사용자가 시작하는 발화"의
권한을 다르게 설계해야 한다.
